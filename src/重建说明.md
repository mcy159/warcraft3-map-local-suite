# 05_重建说明 —— 从本归档重新打出「魔兽争霸联机优化补丁.exe」

> 目标：只靠 `02_源包\` + `03_源码\`，在一台干净的 Windows 上复现出可双击部署的补丁 exe。
> 复现物 = `01_交付成品\魔兽争霸联机优化补丁_最终v3面板_12543784B_E97DC972.exe`
> （12,543,784 B / SHA256 `E97DC972402F41AD32F91BA04C267721545BE5F7ED4C8888356CC5322DFD4945`）

---

## 一、这个 exe 到底是什么

**它不是编译器产物，是「PE 可执行桩 + zip 压缩包」的物理拼接。**

```
偏移 0               14,336              12,543,784
+--------------------+-------------------+
| core2_new.exe      |  suite.zip 内容    |   ← 拼接后整体改名为 .exe
| (PE stub, 14,336B) |  (DEFLATE, 110 项) |
+--------------------+-------------------+
```

- **stub**（`03_源码\core2_new_stub_14336B.exe`，14,336 B）
  是一个真正的 Win32 控制台程序：启动后定位自身 exe 末尾的 zip，解压到当前目录，跑部署逻辑，弹向导。
  双击 exe 时操作系统执行的是它；zip 部分对 PE 加载器是"附加数据"，不影响加载。
- **zip**（`02_源包\` 的全部内容）
  目录条目用 STORED（不压缩），文件条目用 DEFLATE level 9，时间戳统一 1980-01-01。

### 为什么要做「EOCD 绝对化」

普通 zip 拼接（`copy /b stub.exe + a.zip out.exe`）之后，zip 内部记录的所有偏移都还是**相对于 zip 起点**的。
标准解压工具会从文件尾部找 EOCD、拿到 `cd_offset`，然后 `seek(cd_offset)` —— 在拼接文件里这会跳到 stub 区域，zip 打不开。

`pack_exe.py` 的 `absolutize()` 做两件事：

| 位置 | 字段 | 原值 | 改成 |
|---|---|---|---|
| EOCD（`PK\x05\x06`）+16 | `cd_offset`（中央目录起始偏移） | zip 内相对偏移 | `+ stub_size` |
| 每条中央目录记录（`PK\x01\x02`）+42 | `local header offset` | zip 内相对偏移 | `+ stub_size` |

改完之后 `zipfile.ZipFile('out.exe')` 能**直接**打开，条目偏移全部指向真实文件位置。
这就是 `pack_exe.py` 注释里说的"与桌面 exe 结构一致"。

## 二、重建步骤

### 0. 环境

- Windows（本项目实测 Windows + PowerShell 5.1）
- Python 3.10+（归档内实测用 3.14.10）；只用标准库（`zipfile/struct/hashlib/io`），无第三方依赖
- 可选：`.NET Framework 4.x` 的 `csc.exe`（只有需要重编译改键面板时才要）

### 1. 摆好目录

```
WORK\
  pkg\                 ← 把 02_源包\ 的内容整个拷进来（就是 map_local_suite 的内容）
  core2_new.exe        ← 03_源码\core2_new_stub_14336B.exe
  pack_exe.py          ← 03_源码\pack_exe_最新_20261125_1044.py
```

`pkg\` 的正确形态（102 文件 / 31.81 MB）：

```
pkg\
  Game_patched2.dll        13,187,048 B   ← 大图补丁（8MB→1GB）
  war3.bat                       577 B
  使用说明.txt                 9,684 B
  bin\                        72 files     ← YDWE 运行库（YDWEConfig/ydbase/StormLib/SlkLib/LuaEngine/d3d8proxy/CJassHelper…）
  plugin\warcraft3\           13 files     ← JAPI 插件（11 个 dll + config.cfg + dzclient_api.ini）
  version127a\                11 files     ← 1.27a 可执行集 + redist\miles
  tools\                       2 files     ← keybind_panel.exe (59,904) + 可选工具说明.txt
  maps\                        1 file      ← maps\说明.txt
```

> 注意：`pkg\` 里**没有** `core2.exe`、**没有** `keybind.ini`、**没有** `verify.ps1`。
> `core2.exe` 就是 stub 本体，不属于 pkg；`keybind.ini` 由面板首次运行自动生成；补丁侧没有 verify.ps1。

### 2. 改默认路径（或直接用命令行参数）

`pack_exe.py` 顶部三个默认值是按开发机写死的：

```python
DEFAULT_PKG   = r"E:\aiwork\kk_re\deliverable\map_local_suite"
DEFAULT_STUB  = r"E:\aiwork\kk_re\deliverable\core2_new.exe"
DEFAULT_OUT   = r"E:\aiwork\kk_re\verify_tmp\patch_rebuild_test.exe"
DEFAULT_REF   = r"C:\Users\Administrator\Desktop\魔兽争霸联机优化补丁.exe"   # 仅用于对照体积
VERIFY_OUT    = r"E:\aiwork\kk_re\verify_tmp\pack_rebuild_verify.txt"
```

要么改这 5 行，要么全部走命令行（推荐，不改文件）：

```bat
python pack_exe.py ^
  --pkg  "WORK\pkg" ^
  --stub "WORK\core2_new.exe" ^
  --out  "WORK\out\魔兽争霸联机优化补丁.exe" ^
  --reference "" ^
  --level 9
```

- `--level 9` = DEFLATE 最高压缩，对应最终 12.5 MB 那一版
- `--reference ""` = 关掉"对照参考 exe 体积"的提示，干净机器上没有桌面参考文件
- **`--out` 绝不指向桌面**：脚本自己也会警告"绝不触碰桌面 exe"

### 3. 跑

```bat
cd /d WORK
python pack_exe.py --pkg pkg --stub core2_new.exe --out out\patch.exe --reference "" --level 9
```

脚本会依次打印并写入 `pack_rebuild_verify.txt`：

```
stub_size = 14336
stub_md5  = 0B92357560B1A0767DC3A8DD420A4BC5
pkg_files = 102
pkg_dirs  = 12
out_exe_size = ...
out_exe_sha256 = ...
verify_zipfile_open  PASS       ← zipfile 能直接打开 out exe（绝对化成功）
verify_file_count    PASS       ← 条目数 == pkg 文件数
verify_manifest      PASS       ← 名字/大小 0 diff
verify_all_md5       PASS       ← 逐文件 MD5 全等
verify_keybind_panel PASS       ← 59904 B / C5973F2E82B92403863C69BC25239961
verify_head_stub     PASS       ← 头部 == stub 的 MD5
RESULT = ALL CHECKS PASSED
```

**只要 `RESULT` 不是 `ALL CHECKS PASSED`，就不要拿去部署。**

> 脚本里 `verify_dir_count` 期望值是 `10`，当前 pkg 是 `12` 个目录条目 —— 这一项会显示 FAIL 但**不影响结论**：
> 它只是历史常量没跟着目录结构调整。真正决定成败的是 `verify_zipfile_open` / `verify_manifest` / `verify_all_md5`。
> 若要消除这条噪音，把 `check("verify_dir_count", len(dirs2) == 10, ...)` 的 `10` 改成 `12`。

### 4. 打包时会被自动排除的东西

```python
SKIP_DIR_PARTS   = (".git", "__pycache__", ".idea", ".vscode")
SKIP_FILE_NAMES  = (".gitignore", ".gitattributes", ".DS_Store")
SKIP_FILE_SUFFIXES = (".bak", ".boxed_bak", "~")
```

所以 `02_源包` 里如果残留 `.git\`（本归档**没有**复制它，原件里有 117 文件 / 11.3 MB）不会被打进去。
同理 `keybind.exe.bak_v2` 这类备份也不会。

**但要注意 `_v2` / `_bak_v2` 这种不以 `.bak` 结尾的名字不会被排除** ——
`patch_rebuild_v3_report.md` §7 遗留 #1 记录过这个坑：`tools\keybind.exe.bak_v2` 被打进了 exe，文件数 109→110。
最终 v3 版已把整个 `tools\SuWar3Tools\` / `tools\WarKey2017b\` / `tools\skillbar_reader.exe` / `tools\keybind.exe.bak*` 移出 pkg，
脚本里也加了 5 条 `verify_absent_*` 断言确保这些不再出现。

### 5. 需要重编译改键面板时

面板是 C# WinForms，单文件，无 NuGet 依赖。用 .NET Framework 自带的编译器即可：

```bat
C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe ^
  /target:winexe /platform:x86 /optimize+ ^
  /out:tools\keybind_panel.exe ^
  /reference:System.dll /reference:System.Windows.Forms.dll /reference:System.Drawing.dll ^
  keybind_panel_v3_现役面板.cs
```

- 现役面板源码 = `03_源码\keybind_panel_v3_现役面板.cs`（112,012 B / SHA256 `6E8D8F0C96A5FC16643B75DFA51AC23A6F5BD99A162D3F4D1E8D460CDA2FC88D`）
- 编译产物应为 **59,904 B / MD5 `C5973F2E82B92403863C69BC25239961`**（`pack_exe.py` 内置期望值）
- **32 位必须**：面板要 `ReadProcessMemory` 读 32 位 War3 的技能栏/物品栏 hotkey，`/platform:x86` 不能省
- 其余三份面板源码只是历史：`keybind_panel_F7版.cs`（94,578 B，F7 默认热键）、`_历史\keybind_panel_F8版.cs`（94,698 B，F8 默认热键）、`keybind_panel_v2.cs`（未归档，见 04_文档\keybind_panel_v2_report.md）

改键内核 `keybind.cs`（53,168 B）编译方式见 `03_源码\keybind_build.cmd`。

## 五、回滚

- 打包**不修改**任何输入文件（pkg / stub 都是只读打开），失败重跑即可。
- 部署到游戏目录前，先整目录备份 `E:\game\Warcraft III Frozen Throne\`（或至少备份 `Game.dll` / `war3.bat` / `bin\` / `plugin\`）。
- 面板/改键的运行时状态只在内存和 `tools\keybind.ini`，删 ini 即回默认。
